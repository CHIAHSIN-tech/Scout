# Spec — 待買清單：Markdown 匯出（依情境分段）

> **用途**：交給 Stanley（Claude Code）執行的 SSOT。單一小功能。
> **需求來源**：Chia 的購物模組 backlog——「Markdown 匯出（所有資料可匯出 .md，呼應 context.md 生態、local-first）」。
> **維護**：完工後更新 `buylist/BUYLIST_STATE.md`。

---

## 0. Meta
- **Appetite（時間預算）**：小。純前端：把 `items` 組成 markdown 字串 → Blob 下載。無 schema、無後端。
- **Status**：draft
- **Date**：2026-07-25
- **建議順序**：接在 `spec-buylist-context-tag.md`（情境標籤）之後做最順；若先做，沒有 `tag` 欄位時全部歸「未分情境」，程式須容錯。

## 1. Problem Statement
清單資料現在只活在 Supabase / 畫面上，沒辦法整包帶走或貼進別的地方（筆記、給家人看、存進 context.md 生態）。想一鍵把整張待買清單匯成一份 `.md`。

## 2. Primary User + JTBD
- **User**：Chia / Stanley，桌面瀏覽器跑 `buylist/index.html`。
- **JTBD**：當我想把整張清單帶出 app（存檔／分享／貼進筆記），我想要一鍵下載成 `.md`，這樣資料是我自己的、離線也留得住。

## 3. Success Criteria
- 一顆按鈕 → 下載一份 `.md`，內容是**目前全部項目**（不受畫面篩選影響）。
- 內容依**情境（tag）分段**，讀起來就是一份清爽的清單。
- 純本地：不經過任何伺服器、不需網路（Supabase 之外）。

## 4. MoSCoW
- **Must**
  - 一顆「⬇ 匯出 .md」按鈕（放篩選列或頁首附近，不干擾新增區）。
  - 點擊 → 由目前載入的 `items` 組出 markdown 字串 → 用 Blob + `a[download]` 觸發下載，檔名 `buylist-YYYY-MM-DD.md`。
  - **依情境分段**：每個情境（tag）一個 `##` 段落；沒有情境的項目集中在最後一段「## 未分情境」。
  - 每筆一行：`- 名稱　NT$價格　×數量(僅 >1 顯示)　[迫切度]`；已買項目名稱**劃線**（markdown `~~名稱~~`）或前綴 ✓。
  - 匯出**全部**項目（未購＋已買），不受當前 `f-status` / `f-cat` / `f-tag` 篩選影響。
  - 檔尾一行總計：`> 共 N 項，未購合計 NT$X`（X＝未購項目的價格加總，口徑與 app 一致：只加未購）。
- **Should**
  - 段落內：未購在前、已買在後（已買劃線集中段尾），與畫面「已買沉底」精神一致。
- **Could**
  - （無）
- **Won't（這版明確不做）**
  - 只匯出「當前篩選結果」的選項（v1 一律全量；要就之後加）。
  - 依分類或巢狀（情境>分類）分段（已定案走純情境分段）。
  - 匯出成 CSV / JSON / PDF（本 spec 只做 .md）。
  - 匯入（.md 讀回）——只做匯出。
  - 把備註、連結、後續成本、誰加的等全欄位都塞進去（v1 只放 名稱/價格/數量/迫切度，保持清爽）。

## 5. Scope & Interfaces
- **涉及檔案**：只動 `buylist/index.html`（一顆按鈕 + 一個 `buildMarkdown()` + 一個下載函式 + 綁定）。**無 schema、無 DDL、無後端。**
- **既有 pattern 對照**：
  - 資料來源直接用記憶體裡的 `items`（已由現行載入邏輯填好）。
  - 分情境：以 `item.tag`（缺值/空 → 歸「未分情境」）分組；情境段落照名稱排序，「未分情境」永遠最後。
  - 金額格式重用現有 `money()`；迫切度標籤重用 `URG[...]` 的中文 label。
  - 數量重用 `item.quantity`（缺值視為 1，只有 >1 才輸出 `×N`）——與 `spec-buylist-qty-and-bought-bottom.md` 對齊；若數量功能未上，一律不顯示數量即可。
- **明確 out of scope**：不改資料、不改新增/篩選/排序、不碰 Supabase 寫入、不碰 AI。

## 6. Acceptance Criteria（初始全 failing）
- [ ] **AC-1**：點「匯出 .md」→ 瀏覽器下載一個 `buylist-YYYY-MM-DD.md`（日期為當天）。
- [ ] **AC-2**：檔案內容依情境分成多個 `##` 段落；有情境的項目各歸其段。
- [ ] **AC-3**：沒有情境的項目全部集中在最後一段「## 未分情境」。
- [ ] **AC-4**：每筆顯示 名稱、價格（NT$）、迫切度；數量 >1 的顯示 `×N`，數量為 1 或無的不顯示數量。
- [ ] **AC-5**：已買項目名稱以 `~~刪除線~~`（或 ✓ 前綴）呈現，和未購區分得出來。
- [ ] **AC-6**：畫面先切到某個篩選（例如只看「Costco」）再匯出 → 檔案仍含**全部**項目，不受該篩選影響。
- [ ] **AC-7**：檔尾有一行 `> 共 N 項，未購合計 NT$X`，數字正確（X 只加未購項目）。
- [ ] **AC-8**：整個流程不需連外（除既有 Supabase 讀取外），離線點按鈕也能用手上已載入的資料匯出。

## 7. Build Order（一次一件事）
1. **buildMarkdown()**：純函式，吃 `items` 回傳字串（分情境、排序、每筆格式、已買處理、檔尾總計）。可先在 console 印出來驗格式。
2. **下載 + 按鈕**：加按鈕、Blob 下載、檔名帶日期、綁定事件 → 驗 AC-1~AC-8。

## 8. End-to-End Verification
瀏覽器開 `buylist/index.html`，備妥幾筆（含不同情境、一筆未分情境、一筆已買、一筆數量 3）。先把畫面篩選切到某情境，再點「匯出 .md」。打開下載的檔案確認：依情境分段、未分情境在最後、已買劃線、數量 3 顯示 `×3`、檔尾總計正確、且內容是全部而非只有篩選中的那段。

## 10. Open Questions / Risks
- **R1（tag 依賴）**：本功能依情境分段 → 最好在情境標籤功能之後做。若先做，`item.tag` 不存在時全部歸「未分情境」，`buildMarkdown` 對缺欄位須容錯。
- **R2（已買口徑）**：檔尾「未購合計」與 app 頂部「本月未購總價」口徑可能不同（app 只算「本月且未購」，匯出算「全部未購」）。本 spec 採「全部未購」，若要對齊 app 再議。
- **R3（檔名重複）**：同一天多次匯出會同名；瀏覽器通常自動加 `(1)`，v1 不特別處理。
