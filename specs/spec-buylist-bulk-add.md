# Spec — 待買清單：一次貼多行文字批次新增

> **用途**：交給 Stanley（Claude Code）執行的 SSOT。單一小功能。
> **需求來源**：Chia 的購物模組 backlog（2026-07 筆記）——「一次貼多行文字批次新增」。
> **維護**：完工後更新 `buylist/BUYLIST_STATE.md`。

---

## 0. Meta
- **Appetite（時間預算）**：小。一個工作段落內做完；純前端＋一次批次寫入，無 schema 變動。
- **Status**：done（落地 commit `750fda6`）
- **Date**：2026-07-25

## 1. Problem Statement
腦中一次冒出好幾樣要買的東西（例如補貨：衛生紙、洗髮精、咖啡豆），現在只能一筆一筆填表單、按加入，重複又慢。想要「一次全貼進去、自動拆成多筆」。

## 2. Primary User + JTBD
- **User**：Chia / Stanley，桌面瀏覽器跑 `buylist/index.html`，Supabase 同步。
- **JTBD**：當我一次想到好幾樣要買的，我想要把它們一整段貼上、自動拆成多筆加進清單，這樣我不用逐筆填表單。

## 3. Success Criteria
- 貼「衛生紙、洗髮精、咖啡豆」→ 一鍵得到三筆獨立項目。
- 分隔符涵蓋**換行、頓號「、」、逗號（半形 `,` 與全形「，」）**，混用也能正確拆。
- 每筆只帶名稱，其餘走現有預設，不強迫使用者當下填價格/分類。
- 不影響現有的單筆「＋加入」與「🔗貼連結帶入」。

## 4. MoSCoW
- **Must**
  - 新增一個多行輸入框（textarea）＋一顆「批次新增」按鈕，與現有單筆表單並存、不互相取代。
  - 按鈕觸發：以「換行 / 頓號、/ 逗號（, ，）」為分隔符拆分，每段 trim 後成為一筆項目的名稱。
  - 每筆項目欄位：`name` = 拆出的字串；其餘走預設（`price`=0、`urgency`='maybe'、`accessibility`='tw_easy'、`this_month`=true、`category`='其他'、`bought`=false、`added_by`=目前使用者）。
  - 一次批次寫入 Supabase（單次 `insert([...])`），完成後狀態列顯示「已加入 N 筆」。
- **Should**
  - 拆分結果去除空白段與純空白行；**同一次貼上內部**若有完全相同的名稱，只留一筆。
  - textarea 為空或拆不出任何有效名稱時 → 狀態列紅字提示，不送出。
- **Could**
  - （無）
- **Won't（這版明確不做）**
  - 用 AI 解析（這是純文字切分，不呼叫 Gemini；AI 版是既有的「🔗貼連結帶入」）。
  - 批次同時帶價格/分類/迫切度（只帶名稱）。
  - 和「清單裡既有項目」比對去重（只在本次貼上內部去重）。
  - 貼上時解析「品名 100」這種夾帶價格的格式。

## 5. Scope & Interfaces
- **涉及檔案**：只動 `buylist/index.html`（HTML 一個 textarea＋按鈕、JS 一個 parse+批次 insert 函式、綁定事件）。**無 schema 變動、無 Supabase DDL。**
- **落點**：放在現有 `.addbox`（第 140–164 行）下方，或作為 addbox 內可展開的次要區塊；不擠壓現有單筆表單。新增元素 id 建議 `bl-bulk`（textarea）、`bl-bulk-add`（按鈕）。
- **既有 pattern 對照**：
  - 寫入沿用現行 `addItem`（約第 316 行）組物件的欄位與預設值——批次版就是「同樣的預設值物件 × N，一次 insert 陣列」。
  - `added_by` 沿用現行的 `me`（`localStorage.buylist_me`）。
  - 拆分建議正則：`/[\n,、，]+/`，逐段 `.trim()`、濾掉空字串。
- **明確 out of scope**：不改單筆表單、不改月預算加總、不改篩選/排序、不改 2×2 矩陣、不碰 AI 帶入。

## 6. Acceptance Criteria（初始全 failing）
- [ ] **AC-1**：在批次框貼「衛生紙、洗髮精、咖啡豆」按批次新增 → 清單多出三筆，名稱分別正確、無多餘空白。
- [ ] **AC-2**：貼三行（每行一項）→ 拆成三筆。
- [ ] **AC-3**：混用（有換行、也有頓號/逗號）→ 全部正確拆分為對應筆數。
- [ ] **AC-4**：貼的內容含空白行與前後空格 → 空白行被略過、名稱前後空白被去除。
- [ ] **AC-5**：新增出來的每一筆，價格顯示 0（或不顯示）、迫切度「再看看」、分類「其他」、本月想買、`added_by`=目前使用者——與單筆加入的預設一致。
- [ ] **AC-6**：批次框留空按按鈕 → 狀態列出現紅字提示，清單不變、不新增空筆。
- [ ] **AC-7**：同一次貼上有重複名稱（如「衛生紙、衛生紙」）→ 只加入一筆。
- [ ] **AC-8**：批次新增後，另一台裝置（Realtime）也看得到這幾筆。

## 7. Build Order（一次一件事）
1. **UI**：在 addbox 下方加 textarea（`bl-bulk`）＋按鈕（`bl-bulk-add`），先讓它顯示、可輸入。
2. **邏輯**：寫 parse（正則拆分 + trim + 濾空 + 本次去重）→ 組 N 個預設物件 → 單次 `sb.from('buylist_items').insert([...])` → 狀態列回報「已加入 N 筆」＋清空 textarea。空輸入走紅字分支。逐條驗 AC-1～AC-8。

## 8. End-to-End Verification
瀏覽器開 `buylist/index.html`，在批次框貼：
```
衛生紙、洗髮精、咖啡豆
牛奶
麵包, 雞蛋
```
按批次新增 → 清單應多出 6 筆（衛生紙／洗髮精／咖啡豆／牛奶／麵包／雞蛋），每筆走預設值；狀態列顯示「已加入 6 筆」；重整後仍在。

## 10. Open Questions / Risks
- **R1（added_by 未選人）**：若使用者還沒選身分（`me` 為空），沿用現行單筆加入的行為（`added_by` 留空字串），不特別擋。
- **R2（超長貼上）**：一次貼幾十筆時，用單次 `insert([...])` 一個 round-trip 即可，別逐筆 insert；Realtime 會一次帶回。
- **R3（分隔符邊界）**：名稱本身若含逗號/頓號（少見）會被誤拆——本版接受此取捨，不做跳脫。
