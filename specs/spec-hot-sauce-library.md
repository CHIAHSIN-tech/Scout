> **用途**：個人收藏管理 + 多人協作編輯的共用辣醬資料庫

## 1. Problem Statement

**背景**  
CHIA 購買和品嚐過許多辣醬，但資訊散落在各處（備忘錄、手機相簿、購物記錄），導致難以回想。

**現狀**  
- 想再次購買某個好吃的辣醬時，找不到商品連結或購買紀錄
- 不記得該辣醬的特性（辣度、香氣如何）
- 旅行購物時，無法快速比較「之前買過這個嗎？它好吃嗎？」

**目標**  
建立一個**共用的辣醬庫**，任何旅伴可編輯，快速查詢並決定是否重新購買。

## 2. Primary User + JTBD

**User**  
- **角色**：CHIA（主要編輯者）+ 旅伴（協作編輯）
- **技術程度**：初學者 / 非技術人員
- **裝置**：主要手機，偶爾電腦
- **使用情境前**：在超市 / 網路 / 倉庫看到辣醬，想確認「之前評分如何」
- **使用情境後**：快速決定「要不要買」或「加入購物清單」

**JTBD**  
當我想起一個曾經買過、很好吃的辣醬，我想快速找到它的資訊和購買連結，所以我能在用完前再次購買。

**支援工作**
- 當我買了新辣醬，我想立刻記錄（圖片 + 評分），所以我不會忘記
- 當我看到某個辣醬，我想快速查證「我之前評分多少」

## 3. Success Criteria（可衡量的成功）

- [ ] **新增辣醬** ≤ 90 秒（從拍照到存檔）
- [ ] **搜尋查詢** ≤ 10 秒內找到某個辣醬
- [ ] **多人同步** 一個人編輯後，另一個人 ≤ 3 秒看到更新
- [ ] **按回購度排序** 一眼看出「最值得回購的辣醬 Top 5」
- [ ] **手機 UI** 在 390px 寬度下，無橫向捲動

## 4. MoSCoW

### Must（沒有就失敗）
- [ ] 新增辣醬記錄：名稱、商品連結、4 個評分維度（辣度、香氣、CP值、回購度，各 1-5 星）
- [ ] 編輯記錄：旅伴可編輯任何已存在的辣醬（支援多人協作）
- [ ] 查看列表：所有辣醬以列表形式展示，預設按「回購度」排序
- [ ] 刪除記錄：移除某個辣醬記錄
- [ ] 實時同步：多人同時編輯時，變更立即顯示（無須手動刷新）
- [ ] 無帳號分享：複製分享連結給旅伴，無需註冊帳號

### Should（重要但非上線關鍵）
- [ ] 上傳圖片：每個辣醬可附加 1 張圖片（≤ 5 MB）
- [ ] 記錄價格：購買時的價格
- [ ] 記錄購買日期：追蹤「何時買的」

### Could（錦上添花）
- [ ] 分類標籤：例如「泰國」「墨西哥」「自製」等
- [ ] AI 推薦：基於評分推薦「最值得回購的辣醬」

### Won't（這版明確不做）
- [ ] 社群分享：不分享到 Facebook / Instagram / TikTok
- [ ] 電商整合：不整合購物車、不支援一鍵下單
- [ ] 詳細評論區：不支援文字評語或長篇筆記
- [ ] 版本控制：不記錄編輯歷史或誰改了什麼
- [ ] 複雜搜尋：不支援進階篩選（by 地區、品牌等）— 只支援簡單文字搜尋

## 5. Scope & Interfaces

### 涉及的檔案 / 模組

**前端**（Vue 3 + Vite）
- `src/pages/SauceList.vue` — 主列表頁面
- `src/pages/SauceDetail.vue` — 詳細檢視 / 編輯頁面
- `src/components/SauceForm.vue` — 新增 / 編輯表單
- `src/components/SauceCard.vue` — 列表項目卡片
- `src/services/sauceService.js` — Supabase 資料查詢邏輯

**後端**（Supabase）
- **Table: `sauces`** — 辣醬記錄主表
- **Realtime subscriptions** — 多人同步

**部署**
- GitHub Pages（靜態網站）
- Supabase（資料庫 + 實時同步）

### 明確 Out of Scope
- **帳號系統**：無註冊、無密碼、無個人資料頁面
- **評論 / 互動**：無點讚、無留言
- **備份 / 復原**：不提供版本歷史
- **自訂評分維度**：固定 4 個（辣度、香氣、CP值、回購度）
- **複雜報表**：不生成統計圖表

### 要遵循的既有 Pattern

參考已完成專案的模式：
- **身份認證**：比照 Scout Checklist 的「分享連結」模式（URL 參數含 libraryId）
- **多人協作 + 實時同步**：參考 BuyList 的 Firebase Realtime DB 模式，改用 Supabase
- **行動優先 UI**：參考 Scout Checklist 的卡片設計和響應式佈局
- **資料庫結構**：遵循 12-Factor App 的設定外部化（API Key 放環境變數）

## 6. Acceptance Criteria（使用者視角 end-to-end）

### Create
- [ ] **AC-1**：使用者進入分享連結 → 看到現有辣醬列表（空的如果是首次）
- [ ] **AC-2**：使用者點「新增辣醬」→ 填入名稱、URL、4 個評分 → 點「存檔」→ 列表立刻更新，新辣醬出現在最下方
- [ ] **AC-3**：如果評分欄位為空，無法儲存（驗證訊息顯示「所有維度必填」）

### Read
- [ ] **AC-4**：使用者開啟頁面 → 所有辣醬按「回購度」降序排列（5 星在上）
- [ ] **AC-5**：列表中每個辣醬卡片顯示：名稱、主評分（辣度 X 星）、可點擊進入詳細頁
- [ ] **AC-6**：使用者在搜尋框輸入「辣」→ 列表過濾，只顯示名稱包含「辣」的記錄

### Update
- [ ] **AC-7**：使用者點某個辣醬卡片 → 進入詳細頁，看到所有欄位（名稱、URL、4 個評分、圖片、價格、購買日期）
- [ ] **AC-8**：在詳細頁修改任何欄位 → 點「保存」→ 列表自動重新排序（如改了回購度）
- [ ] **AC-9**：使用者 A 在編輯，使用者 B 同時查看列表 → 使用者 A 存檔後，使用者 B 的列表 ≤ 3 秒內更新（無需刷新）

### Delete
- [ ] **AC-10**：使用者在詳細頁點「刪除」→ 出現確認對話 → 確認後，該記錄從列表消失

### Image Upload
- [ ] **AC-11**：使用者在編輯表單點「上傳圖片」→ 選擇本機照片 → 預覽縮圖 → 儲存時一併上傳到 Supabase Storage
- [ ] **AC-12**：詳細卡片 / 列表卡片顯示圖片縮圖（如果有）

### Multi-user
- [ ] **AC-13**：兩個使用者用同一分享連結進入 → 各自編輯不同辣醬 → 兩人都能看到彼此的變更（Realtime sync）

## 7. Build Order（一次一件事）

**第 1 loop：基礎列表 + CRUD（Create, Read, Update, Delete）**
1. 初始化 Vue 3 + Vite 專案
2. 連接 Supabase（環境變數 + 初始化）
3. 定義 `sauces` table schema（id, name, url, ratings[spiciness/aroma/cpValue/repurchase], createdAt, updatedAt）
4. 建立 `SauceList.vue` — 從 Supabase 讀取 & 顯示卡片列表（按回購度排序）
5. 建立 `SauceForm.vue` — 新增辣醬表單（驗證 4 個評分都必填）
6. 連接「新增」功能 → Supabase insert
7. 測試：能新增、看到在列表上
8. **Tracer bullet 停止點**：新增一個測試辣醬，確認能在列表看到

**第 2 loop：編輯 + 刪除**
1. 建立 `SauceDetail.vue` — 詳細檢視 & 編輯表單
2. 連接「編輯」功能 → Supabase update
3. 連接「刪除」功能 → Supabase delete（含確認對話）
4. 測試：編輯後列表重新排序，刪除後消失

**第 3 loop：實時同步 + 搜尋**
1. Supabase Realtime subscription（監聽表變更）
2. 列表自動重新整理（新增 / 編輯 / 刪除）
3. 搜尋框過濾（客戶端過濾或伺服器端搜尋）
4. 測試：兩個瀏覽器分頁，一個編輯時另一個立即看到變化

**第 4 loop：圖片上傳（Should 功能）**
1. 加 imageUrl 欄位到 table
2. 表單新增「上傳圖片」檔案輸入
3. 連接 Supabase Storage（上傳到 `sauce-images/` 資料夾）
4. 列表 / 詳細頁顯示圖片縮圖
5. 測試：上傳圖片，刷新後仍存在

**第 5 loop：價格 + 購買日期（Should 功能）**
1. 加 price, purchaseDate 欄位到 table
2. 表單新增欄位（價格數字輸入、日期選擇器）
3. 詳細卡片顯示這些欄位
4. 測試：能儲存並顯示

**第 6 loop：無帳號分享 + 部署**
1. URL 參數含 libraryId（例如 `/sauce-library?lib=abc123`）
2. 每個分享連結映射到一個 library（Supabase 可做 Row Level Security）
3. 部署到 GitHub Pages
4. 測試：兩個不同連結是獨立的辣醬庫

## 8. End-to-End Verification

**使用者故事的完整驗收**

1. **初始化**
   - 開啟分享連結 → 看到空列表（或既有辣醬）

2. **新增辣醬**
   - 點「+新增」
   - 填入：「Lee Kum Kee 辣豆瓣醬」
   - 輸入 URL：`https://example.com/sauce/123`
   - 設定評分：辣度 4, 香氣 5, CP值 3, 回購度 5
   - 點「存檔」
   - **驗證**：列表重新整理，該辣醬以卡片形式出現，主評分顯示「辣度 4★」

3. **搜尋**
   - 在搜尋框輸入「Kum Kee」
   - **驗證**：只顯示該記錄

4. **編輯**
   - 點卡片進入詳細頁
   - 改評分：辣度 5, 香氣 5, CP值 4, 回購度 5
   - 點「保存」
   - **驗證**：列表重新排序，該辣醬因回購度 5 移到最上方

5. **多人同步**
   - 打開第二個瀏覽器分頁（同一連結）
   - 在第一分頁新增另一個辣醬「Frank's RedHot」
   - **驗證**：第二分頁 ≤ 3 秒內自動更新（無需手動刷新）

6. **刪除**
   - 在詳細頁點「刪除」
   - 確認刪除
   - **驗證**：回到列表，該記錄已移除

7. **圖片上傳**（Should 功能，如時間允許）
   - 上傳某個辣醬的圖片
   - **驗證**：卡片顯示圖片縮圖，詳細頁也能看到

## 10. Open Questions / Risks

### 已決定
- ✅ 後端：Supabase（而非 Firebase）
- ✅ 前端：Vue 3 + Vite
- ✅ 評分維度：固定 4 個（辣度、香氣、CP值、回購度）
- ✅ 主評分：辣度（用於主卡片顯示）
- ✅ 身份驗證：無帳號，分享連結

### 待決定
- [ ] **Row Level Security（RLS）設定**：是否限制「只有分享連結的使用者才能編輯」？目前假設開放（任何人知道連結就能編輯）
- [ ] **Image resize / compression**：上傳圖片時自動壓縮嗎？目前無特殊處理
- [ ] **離線支援**：需要 Service Worker 做離線存取嗎？目前不做

### 已知風險
- 🚩 **Supabase 免費層限制**：連線數 / 儲存空間，100 個記錄應該沒問題，但如果加圖片要監控 Storage 配額
- 🚩 **圖片 CDN**：Supabase 預設圖片 URL 可能較慢，大量圖片時考慮加 CDN
- 🚩 **無帳號的編輯衝突**：兩人同時編輯同一筆記錄，後存檔的會覆蓋先前的（無版本控制）— 這是 Won't 項目
